# Context: Lab C Phase 2 Step 1-2 — NPC Embodiment (Data Foundation + Movement System)

เป้าหมาย: NPC มี Stats/Inventory และเคลื่อนที่ในโลก Walking Sandbox จริง
Scope รอบนี้: เดินสุ่ม (Wander) ในโซนปัจจุบัน + เตรียม Inventory สำหรับ Killer

# Architecture Constraints (เคร่งครัด)
1. VContainer: Resolve ผ่าน GetComponentInParent<GameLifetimeScope>().Container
2. MessagePipe: NpcLocationChangedMessage.Publish ผ่าน MoveNpc() เท่านั้น
3. MVP Lite + Information Hiding: PositionX/Y, Inventory, Fear, Curiosity = Ground Truth
   ห้ามหลุดเข้า NpcObservableView / GetObservableNpcsAt เด็ดขาด
4. MessagePack Keys: NpcState ใช้ 0-8 อยู่แล้ว — ฟิลด์ใหม่เริ่มที่ [Key(9)] เป็นต้นไป ห้ามชน
5. Single Source of Truth: CurrentLocationId เปลี่ยนผ่าน MoveNpc() เท่านั้น

# Context: Lab C Phase 2 Step 3 — NPC Visual Sync (chibi follows NpcState.Position)

Step 1-2 เสร็จแล้ว ทำให้ chibi บนจอเดินตาม PositionX/Y จริง

# Architecture Constraints
- MVP Lite: per-frame sync = direct method call (บทเรียน Lab 13) — ห้ามใช้ MessagePipe ต่อเฟรม
- ใช้ interface IChibiVisual เท่านั้น (GenericCute + Spine ต้องทำงานทั้งคู่)
- Information Hiding: View อ่าน Position/Activity ได้ (ตาเห็นอยู่แล้ว)
  แต่ห้าม render หรือ expose Inventory/Fear/Curiosity

## 3.1 NpcCharacterView.cs (MonoBehaviour — 1 ตัวต่อ chibi)
- ChibiSpawnerView ติดตั้งตอน SpawnChibi ผ่าน Init(npcId, npcDirector) แบบ direct call
- Update(): อ่าน NpcState → transform.position = (PositionX, PositionY, 0)
- Facing: flip จากเครื่องหมาย delta การเคลื่อนที่แนวนอน
- Animation: เรียก IChibiVisual.Bind(npc.Activity)

## 3.2 ⚠️ Enum ที่ถูกต้อง: NpcActivityState = { Idle, Gathering, Resting, Traveling, Talking }
- **ไม่มี Walking** — การเคลื่อนที่ใช้ `Traveling` (pattern เดียวกับ PlayerMovementSystem)
- NpcMovementSystem ตั้ง Activity = Traveling ขณะเคลื่อนที่, Idle เมื่อถึงเป้า
- ตรวจว่า GenericCuteVisualController.Bind() มี case ของ Traveling → anim "walk" แล้ว
  ถ้ายังไม่มีให้เพิ่ม (Spine controller เช่นกัน)

## 3.3 ChibiSpawnerView
- ตอน SpawnChibi: init NpcCharacterView + ตั้งตำแหน่งจาก PositionX/Y ทันที
  (เฟรมแรกต้องไม่โผล่ที่ origin — Update() จะทับ offset เดิมทันที)
- ห้ามแตะ despawn / prefab rotation / backend toggle เดิม
- Player ไม่เกี่ยว — PlayerCharacterView ยังเป็นเจ้าของ transform ผู้เล่น

## 3.4 Runtime Tests
- A: NPC เดินวนใน beach เห็นชัด, anim walk ตอน Traveling, idle ตอนหยุด, flip ถูก
- B: ข้ามโซน → despawn/respawn ผ่าน message flow เดิม ไม่มี transform แย่งกัน
- C: backend = Spine → การเดินเดียวกันโผล่บน rig Spine
- D: regression — player movement/camera/pickup และ get_visible_npcs ไม่เปลี่ยน
- screenshot A และ C

# Context: Lab C Phase 2 Step 4 — Basic AI Hook (InnocentUtilityAI + KillerPlanner)

แทนที่ TryAttemptElimination (สุ่ม 15%/tick) ด้วยสมองแยกตาม role
hook เข้า NpcDirectorSystem.TickBehavior ที่ว่างอยู่

# Architecture Constraints
- ⚠️ Tick Order: NpcDirectorSystem.Tick() (ตั้ง target) รันก่อน NpcMovementSystem.Tick() (เดิน)
- ⚠️ DI: Register InnocentUtilityAI + KillerPlanner เป็น Lifetime.Singleton
  ใน GameLifetimeScope.Configure() แล้ว inject เข้า NpcDirectorSystem constructor
  ห้าม new เองใน constructor ของ system (ข้าม container)
- ทั้ง Killer และ Player ฆ่าผ่าน TryEliminate/CanEliminate เท่านั้น ห้ามมีกฎฆ่าเส้นที่สอง
- Information Hiding: KillerPlanState / NpcSurvivalState / NpcInventory = Ground Truth
  ห้ามโผล่ใน NpcObservableView, GetObservableNpcsAt, GetGameStateHandler หรือ MCP response ใดๆ
- Design Decision (ปิดแล้ว): TryEliminate/CanEliminate **ไม่รับ weaponCardId param**
  และคงความ economy-agnostic — การเช็คอาวุธเป็นหน้าที่ caller:
  ผู้เล่น → UseCardHandler (TryConsume ก่อน), NPC → KillerPlanner (HasWeapon ก่อน Executing)
  อาวุธ NPC ไม่ถูกหักตอนฆ่าในรอบนี้ (role-enabling condition) — TODO: durability ในอนาคต

## 4.1 ⚠️ Deprecate re-target-on-arrival ของ Step 2
- ปิด logic สุ่ม target ตอนถึงเป้าใน NpcMovementSystem ทิ้ง (method PickNextTarget())
- NpcMovementSystem เหลือหน้าที่เดียว: "เดินเข้าหา Target ที่มีอยู่ตอนนี้"
- การเลือก Target ใหม่ทั้งหมดย้ายไป IUtilityAction / KillerPlanner
  (กันสองระบบแย่งกันเซ็ต TargetX/Y — undefined behavior)

## 4.2 namespace Marooned.Systems.AI
- IUtilityAction { Id, Score(npc, ctx), Execute(npc, ctx, dt) }
- UtilityContext { Data, NpcDirector, StateProvider } สร้างครั้งเดียวต่อการ re-evaluate
- InnocentUtilityAI: re-evaluate ทุก ~1.5 วิต่อตัว (กัน jitter) แล้ว execute ทุก tick
  - Implement จริง: IdleWanderAction (สุ่มจุดใน location ปัจจุบัน),
    SeekFoodAction (score = Hunger normalize; execute = เดินไป location ที่มี food,
    ถ้า inventory มี food card → consume + คืน Hunger)
  - Stub (score 0): InvestigateNoiseAction, FleeToSafeZoneAction
- KillerPlanner: KillerPhase = Patrolling → SeekingWeapon → SeekingOpportunity → Executing → BuildingAlibi
  - Patrolling: เดินสุ่มเหมือน innocent (reuse IdleWander logic)
  - SeekingWeapon: HasWeapon(Category==Weapon)? มี → SeekingOpportunity,
    ไม่มี → เดินไป location ที่ loot table มีการ์ด Weapon
  - SeekingOpportunity: เคารพ KillCooldownRemaining; CanEliminate (dry-run)
    หาเหยื่อใน location เดียวกัน → Executing
  - Executing: เช็ค CanEliminate ซ้ำ → ผ่านจึง TryEliminate;
    สำเร็จ → BuildingAlibi + รีเซ็ต cooldown; ล้มเหลว → กลับ SeekingOpportunity
  - BuildingAlibi: เดินไป connected location ที่มี NPC ที่ยังมีชีวิตอื่น ≥1 ตัว;
    timeout 30 วิ → Patrolling

## 4.3 Hook + Cleanup Checklist (ติ๊กให้ครบ)
