# Context: Fix MoveToLocation — Player ต้องเดินจริง ไม่ใช่ Teleport

ปัญหา: ตอนนี้ AI VTuber สั่ง MoveToLocation แล้วตัวละคร teleport ทันที (เปลี่ยน CurrentLocationId แต่ PositionX/Y ไม่ขยับ)
สาเหตุ: Player ไม่มีระบบ Auto-Move เหมือน NPC (NpcMovementSystem มี TargetX/TargetY แต่ PlayerSurvivalState ไม่มี)

# Architecture Constraints (เคร่งครัด)
- VContainer: Resolve ผ่าน GetComponentInParent<GameLifetimeScope>().Container
- MessagePipe: ใช้ PlayerLocationChangedMessage เมื่อถึงปลายทาง
- MVP Lite: System (Plain C#) คำนวณตำแหน่ง → View (PlayerCharacterView) อัปเดต Transform
- MessagePack Keys: PlayerSurvivalState ใช้ Key 0-14 อยู่แล้ว — ฟิลด์ใหม่เริ่มที่ [Key(15)] เป็นต้นไป
- Single Source of Truth: PositionX/Y ต้องถูกอัปเดตโดย PlayerMovementSystem หรือ PlayerAutoMoveSystem เท่านั้น

# Task: เพิ่ม Player Auto-Move System

## Step 1: เพิ่ม Field ใน PlayerSurvivalState.cs (Key >= 15)
เพิ่มฟิลด์ต่อไปนี้ (ต่อจาก Key 14 ที่มีอยู่แล้ว):
- [Key(15)] public float TargetX;
- [Key(16)] public float TargetY;
- [Key(17)] public bool IsAutoMoving;

⚠️ **สำคัญ**: รัน `sync-shared.sh` หลังแก้ไฟล์นี้ (เพราะเป็นไฟล์ Shared ที่ใช้ทั้ง Unity และ McpBridge)

## Step 2: สร้าง PlayerAutoMoveSystem.cs (Plain C# Singleton)
- รับ PlayerSurvivalState ผ่าน Constructor
- มี Speed = 3.5f (ให้ตรงกับ PlayerMovementSystem)
- มี method Tick(float dt):
  - ถ้า !IsAutoMoving → return ทันที
  - คำนวณระยะห่างระหว่าง (PositionX, PositionY) และ (TargetX, TargetY)
  - ถ้าระยะ <= 0.1f → Set IsAutoMoving = false, Activity = Idle → return
  - เลื่อน PositionX/Y เข้าหา Target ด้วย Speed * dt
  - Set Activity = Traveling
  - ปรับ FacingRight ตามทิศทาง (dx > 0)

## Step 3: แก้ไข PlayerMovementSystem.cs
- เพิ่มเช็กตอนต้น Tick(): `if (_player.IsAutoMoving) return;`
  (กัน Keyboard แย่ง Control ระหว่างเดินอัตโนมัติ)
- หมายเหตุ: PlayerInputService ยังทำงานปกติ — แค่ไม่ส่งผลตอน IsAutoMoving = true

## Step 4: แก้ไข MoveToLocationHandler.cs
- แทนที่จะ set CurrentLocationId ทันที ให้:
  1. อ่าน LocationDef ของปลายทาง (targetDef)
  2. ตั้งค่า:
     ```csharp
     player.TargetX = targetDef.WorldX;
     player.TargetY = targetDef.WorldY;
     player.IsAutoMoving = true;
     ```
  3. **รอจนกว่า IsAutoMoving = false** (เดินถึงจริง) โดยใช้ McpMainThreadDispatcher:
     ```csharp
     await _mainThread.WaitUntilAsync(() => !player.IsAutoMoving);
     ```
     (ถ้าไม่มี method นี้ ให้เพิ่มใน McpMainThreadDispatcher.cs ด้วย)
  4. เมื่อถึงแล้ว → set `CurrentLocationId = request.LocationId`
  5. Publish `PlayerLocationChangedMessage`

## Step 5: เพิ่ม WaitUntilAsync ใน McpMainThreadDispatcher.cs (ถ้ายังไม่มี)
```csharp
public async UniTask WaitUntilAsync(Func<bool> predicate, float timeout = 30f)
{
    var timer = 0f;
    while (!predicate() && timer < timeout)
    {
        await UniTask.Yield(PlayerLoopTiming.Update);
        timer += Time.deltaTime;
    }
}
```

## Step 6: อัปเดต Python Proxy (main.py)
- ลบหรือลด `behavior.travel_time()` ออก (เพราะเกมเดินจริงแล้ว ไม่ต้องหน่วงซ้ำ)
- เหลือแค่ `thinking_delay()` ก่อนเริ่มเดินพอ
- หรือ comment out ส่วน travel_time ชั่วคราวเพื่อเทส

## Step 7: Runtime Tests
- Test A: สั่ง MoveToLocation("jungle_edge") → ตัวละครต้องเดินจากจุดเดิมไปยัง WorldX/Y ของ jungle_edge จริง (เห็นบนจอ)
- Test B: ระหว่างเดิน Activity = Traveling, ถึงแล้ว → Activity = Idle
- Test C: กด WASD ระหว่างเดินอัตโนมัติ → ไม่ตอบสนอง (IsAutoMoving ป้องกันอยู่)
- Test D: เมื่อเดินถึง → CurrentLocationId เปลี่ยน, BiomeScatterView เปลี่ยนฉาก, ChibiSpawnerView despawn/spawn NPC ถูกต้อง
- Test E: Python log ไม่หน่วงนานเกินจริง (ลบ travel_time ออกแล้ว)

# Context: UI Migration — Legacy Text/TextMesh → TextMeshPro (THSarabunPSK)

เป้าหมาย: เปลี่ยนระบบข้อความทั้งหมดในเกมจาก Legacy Unity Text/TextMesh เป็น TextMeshPro 
เพื่อรองรับฟอนต์ภาษาไทย THSarabunPSK และคุณภาพข้อความที่ดีขึ้น

# ⚠️ Prerequisites (ต้องทำใน Unity Editor ก่อนรันโค้ด)

## 1. เตรียม Font Asset
- เปิด `Window > TextMeshPro > Font Asset Creator`
- เลือก Source Font: `THSarabunPSK` (ไฟล์ .ttf ที่มีอยู่)
- Character Set: Dynamic
- Generate และ Save เป็น `THSarabunPSK SDF.asset`
- **สำคัญ**: ย้ายไฟล์นี้ไปไว้ที่ `Assets/Resources/Fonts/THSarabunPSK SDF.asset`
  (Resources.Load ต้องการ path ใต้โฟลเดอร์ Resources เท่านั้น)

## 2. อัปเดต Prefabs
- `CardSlot.prefab`: เปลี่ยน component ของ label จาก `Text` → `TextMeshProUGUI`
  - ลบ component Text เก่าออก
  - Add Component: TextMeshProUGUI
  - ลาก field `label` ใน Inspector ใหม่ให้ชี้ component ที่ถูกต้อง

## 3. Canvas Scaler Setting
- เลือก GameObject `Canvas` (ที่ครอบ CardHandContainer)
- หา component `Canvas Scaler`
- ตั้งค่า:
  - UI Scale Mode: **Scale With Screen Size**
  - Reference Resolution: 1920 × 1080
  - Screen Match Mode: Match Width Or Height
  - Match: 0.5

# Architecture Constraints
- ใช้ `TMP_Text` เป็น type สำหรับ UI (แทน `Text`)
- ใช้ `TextMeshPro` สำหรับ World-Space text (แทน `TextMesh`)
- โหลดฟอนต์ผ่าน `Resources.Load<TMP_FontAsset>("Fonts/THSarabunPSK SDF")`
- ใช้ `TextAlignmentOptions.Center` (แทน `TextAnchor.MiddleCenter`)
- Font Size สำหรับ World-Space: 4 (เล็กกว่า TextMesh มาก)
- Font Size สำหรับ UI: 22-24

# Task: แก้ไข 6 ไฟล์หลัก

## Step 1: WorldItemSystem.cs (World-Space Item Labels)
- เพิ่ม `using TMPro;`
- เปลี่ยน `_labelFont` type จาก `Font` → `TMP_FontAsset`
- ใน `Initialize()`:
  ```csharp
  _labelFont = Resources.Load<TMP_FontAsset>("Fonts/THSarabunPSK SDF");
  if (_labelFont == null)
      Debug.LogError("[WorldItemSystem] หา TMP_FontAsset 'THSarabunPSK SDF' ไม่เจอใน Resources/Fonts/");
  ```
- ใน `CreateWorldItem()`:
  ```csharp
  var label = labelGo.AddComponent<TextMeshPro>();
  label.text = displayName;
  label.font = _labelFont;
  label.fontSize = 4;  // TMP world-space ใช้เลขเล็กกว่า TextMesh มาก
  label.alignment = TextAlignmentOptions.Center;
  // ลบบรรทัด label.anchor และ characterSize ออก (ไม่มีใน TMP)
  ```
