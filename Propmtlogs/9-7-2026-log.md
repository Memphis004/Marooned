# Context: Lab B Phase 5 — UI Setup Automation (CardHandView)

โค้ด UI เขียนเสร็จแล้วจาก AI อีกตัว (5 ไฟล์: GameMessages.cs, CardInventorySystem.cs, CardSlotUI.cs, CardHandView.cs, CardHandPresenter.cs, GameLifetimeScope.cs)
ตอนนี้ต้อง setup ฝั่ง Unity Editor (Canvas, Container, Prefab, Attach View) และเทส runtime

# 📂 โค้ดที่มีอยู่แล้ว (ห้ามเขียนซ้ำ — แค่ใช้)
- `Assets/Scripts/UI/CardSlotUI.cs` — placeholder card visual
- `Assets/Scripts/UI/CardHandView.cs` — passive MVP Lite view
- `Assets/Scripts/UI/CardHandPresenter.cs` — plain C# singleton, subscribe message
- `Assets/Scripts/Shared/GameMessages.cs` — มี `CardInventoryChangedMessage` แล้ว
- `Assets/Scripts/Systems/CardInventorySystem.cs` — publish message แล้ว
- `Assets/Scripts/Core/GameLifetimeScope.cs` — register แล้ว

# Architecture Constraints (เหมือนเดิม)
- VContainer: CardHandView ต้องอยู่ใน hierarchy ของ GameLifetimeScope (RegisterComponentInHierarchy)
- MVP Lite: View = MonoBehaviour passive, Presenter = plain C# singleton
- ห้ามแก้โค้ด UI ที่เขียนเสร็จแล้ว — แค่ setup + test

# Task: เขียน Editor Script เพื่อ Automate UI Setup + Runtime Test

## Step 1: เขียน Editor Script (`Assets/Editor/UiSetupAutomation.cs`)
สร้าง Editor Script ที่ทำงานใน Unity Editor (ไม่ต้องเข้า Play Mode) เพื่อ:
1. สร้าง Canvas (ถ้ายังไม่มี) — Render Mode = Screen Space - Overlay
2. สร้าง CardHandContainer (Empty GameObject) ใต้ Canvas:
   - Anchor = bottom-stretch
   - Height = 120
   - เพิ่ม Horizontal Layout Group (Spacing = 10, Child Alignment = Middle Center, Control Child Size = Width + Height)
3. สร้าง CardSlot Prefab:
   - สร้าง GameObject ชื่อ "CardSlot" (100x120)
   - ข้างในมี Image (ชื่อ "Icon") + Text (ชื่อ "Label", วางที่ขอบล่าง)
   - ติด CardSlotUI component ที่ Root
   - ลาก Image/Text เข้าช่อง icon/label ใน Inspector
   - Save เป็น Prefab ที่ `Assets/Prefabs/UI/CardSlot.prefab`
4. สร้าง GameObject ชื่อ "CardHandSystem" ใต้ GameLifetimeScope:
   - ติด CardHandView component
   - ลาก CardHandContainer ใส่ช่อง `cardSlotContainer`
   - ลาก CardSlot Prefab ใส่ช่อง `cardSlotPrefab`
5. Save Scene

**หมายเหตุ:** ใช้ `UnityEditor` namespace + API เช่น `PrefabUtility.SaveAsPrefabAsset`, `Undo.RecordObject` ฯลฯ

## Step 2: รัน Editor Script
- เรียก method `[MenuItem("Marooned/Setup CardHand UI")]` จาก Unity Editor menu
- หรือเรียกจาก Editor Script โดยตรง (ถ้าทำได้ผ่าน MCP)
- ยืนยันว่า Hierarchy มี Canvas > CardHandContainer + CardHandSystem ใต้ GameLifetimeScope

## Step 3: Runtime Test (เข้า Play Mode)
- กด Play ใน Unity
- ใช้ MCP tool `explore_location("beach")` หลายๆ ครั้ง (หรือเรียก `CardInventorySystem.TryAdd` โดยตรงผ่าน test script)
- ควรเห็น:
  - การ์ดสีตาม category เด้งขึ้นจากล่างจอ (เขียว=Resource, ส้ม=Craftable, ฯลฯ)
  - ถ้าเจอการ์ดซ้ำ → ตัวเลข count เพิ่มขึ้น + การ์ด pulse (ไม่ draft ซ้ำ)
- ถ่าย screenshot Game View เป็นหลักฐาน

## Step 4: Cleanup
- ลบ Editor Script (`UiSetupAutomation.cs`) หลัง setup เสร็จ (กัน clutter)
- ยืนยันว่า scene บนดิสก์สะอาด (มี Canvas + CardHandSystem ครบ)

# Output Requirements
- รายงานว่า Editor Script ทำงานสำเร็จไหม
- หลักฐาน runtime test (screenshot + log)
- ระบุปัญหาที่เจอ (ถ้ามี) เช่น LayoutRebuilder, NullReference, etc.

# ️ จุดที่อาจมีปัญหา (จากที่ AI อีกตัวเตือนไว้)
1. `LayoutRebuilder.ForceRebuildLayoutImmediate` ต้องเรียกหลัง `Instantiate` และก่อนอ่าน `anchoredPosition` — ถ้าลืม การ์ดจะโผล่จาก (0,0) แทนที่จะไล่ตำแหน่งจริง
2. `CardHandPresenter` เป็น Singleton ที่ผูกกับ `ISubscriber<CardInventoryChangedMessage>` — ถ้า Unity error ว่า resolve ไม่ได้ ให้เช็คว่า `builder.RegisterMessagePipe()` ถูกเรียกไปแล้วใน GameLifetimeScope
3. ลืมลาก reference ใน Inspector (`cardSlotContainer`, `cardSlotPrefab`, `icon`, `label`) → NullReferenceException ทันทีตอน Play

# Task: Wire Card Interactions (Minimum Viable — Click to Use)

ตอนนี้ CardHandView แสดงการ์ดได้แล้ว แต่ยัง "คลิกไม่ได้" 
ให้เพิ่ม interaction ขั้นต่ำเพื่อให้ผู้เล่นใช้การ์ดจากมือได้

## Requirements (ทำแค่ก่อน)
1. **CardSlotUI — เพิ่ม Click Handler:**
   - ติด `IPointerClickHandler` (UnityEngine.EventSystems)
   - เมื่อคลิก → เรียก method ใน `CardHandPresenter.UseCardFromSlot(cardId)`

2. **CardHandPresenter — เพิ่ม UseCardFromSlot:**
   - รับ `cardId` จาก View
   - ตรวจสอบว่าการ์ดประเภทไหน:
     - ถ้า `CardTargetType.Self` → เรียก `UseCardHandler` ทันที (เช่น กินอาหาร)
     - ถ้า `CardTargetType.SingleTarget` → เปิดโหมด "เลือกเป้าหมาย" (รอคลิก NPC)
   - เรียก `UseCardHandler.InvokeAsync()` → แสดงผล Success/Failure

3. **Target Selection Mode (สำหรับ Weapon):**
   - เพิ่ม flag `_isSelectingTarget` ใน Presenter
   - เมื่อใช้การ์ด Weapon → set flag = true + highlight cursor
   - คลิกที่ NPC (ChibiSpawnerView ต้อง expose method ให้คลิกได้) → ส่ง `TargetId` ไปใช้การ์ด
   - ยกเลิกถ้าคลิกที่ว่าง

4. **UI Feedback:**
   - แสดง FailureReason จาก UseCardResponse บน UI (เช่น "มีคนเห็น!")
   - การ์ดที่ใช้แล้วหายจากมือ (Inventory อัปเดตอัตโนมัติ)

## Constraints
- ยังไม่ต้องทำ Drag-and-Drop (ทำแค่คลิก)
- ใช้ MVP Lite pattern (View = passive, Presenter = logic)
- ถ้า NPC ยังไม่มี click handler ให้เพิ่มใน `ChibiSpawnerView` หรือ `GenericCuteVisualController`

## Output
- CardSlotUI.cs (เพิ่ม OnPointerClick)
- CardHandPresenter.cs (เพิ่ม UseCardFromSlot + target selection logic)
- ทดสอบ: คลิกการ์ดอาหาร → stat เพิ่ม, คลิกการ์ดมีด → เลือก NPC → ฆ่าสำเร็จ/ล้มเหลว

# Context: Lab B Phase 6 — Camera Follow & Zone Transition Triggers

ปัจจุบัน Player เดินได้แต่ติดอยู่ในกรอบ hardcoded และกล้องไม่ตาม ทำให้หลุดจอ
เราต้องเพิ่ม 2 สิ่งเพื่อให้การเดินสำรวจ (Walking Sandbox) สมบูรณ์แบบ:
1. กล้องตามผู้เล่น (Camera Follow)
2. ระบบเปลี่ยนโซนอัตโนมัติเมื่อเดินชนขอบเขต (Zone Transition Trigger)

# Architecture Constraints (เคร่งครัด)
- VContainer: Resolve ผ่าน `GetComponentInParent<GameLifetimeScope>()` ใน `Start()`
- MessagePipe: ใช้ `IPublisher<PlayerLocationChangedMessage>` เมื่อเปลี่ยนโซน
- MVP Lite: View layer แยกจาก Logic ชัดเจน
- ⚠️ **สำคัญ**: ใน `RoundInitializer.cs` บรรทัดที่เรียก `_stateProvider.Player.CurrentLocationId` ให้เปลี่ยนเป็น `_stateProvider.GetPlayer().CurrentLocationId` ทันที (ตาม Architecture Refactor ที่ทำไปก่อนหน้า)

## Step 1: CameraFollow.cs (View Layer)
- สร้างสคริปต์ `CameraFollow.cs`
- มี `[SerializeField] private Transform target;` (สำหรับลาก Player GameObject ใส่)
- มี `[SerializeField] private float smoothSpeed = 0.125f;`
- ใน `LateUpdate()`: ใช้ `Vector3.Lerp` ให้กล้องเคลื่อนที่ตาม target อย่างนุ่มนวล (เฉพาะแกน X, Y, เก็บ Z ไว้ที่ -10 หรือค่าเดิม)

## Step 2: ZoneTransitionTrigger.cs (Logic/Event Layer)
- สร้างสคริปต์ `ZoneTransitionTrigger.cs`
- มี `[SerializeField] private string targetLocationId;`
- มี `[SerializeField] private string playerTag = "Player";`
- ใน `Start()`: Resolve `GameStateProvider` และ `IPublisher<PlayerLocationChangedMessage>` จาก `GameLifetimeScope`
- ใน `OnTriggerEnter2D(Collider2D other)`:
  - เช็ก `other.CompareTag(playerTag)`
  - เช็กว่า `player.CurrentLocationId != targetLocationId`
  - ถ้าใช่: อัปเดต `player.CurrentLocationId = targetLocationId` และ Publish `PlayerLocationChangedMessage`
  - (นี่จะทำให้ `ChibiSpawnerView` ที่ subscribe ไว้ ทำงาน ReconcileChibis อัตโนมัติ!)

## Step 3: PlayerMovementSystem Adjustment
- เปลี่ยน hardcoded bounds (`MinX = -11f`, etc.) ให้เป็น `[SerializeField]` เพื่อให้ปรับขนาด "แผนที่รวม" ได้ง่ายใน Inspector

## Step 4: Unity Editor Setup Instructions (สำหรับฉัน)
- บอกวิธีตั้งค่า Player GameObject: ต้องใส่ Tag = "Player" และต้องมี `Collider2D` (เช่น CircleCollider2D) เพื่อให้ Trigger ทำงาน
- บอกวิธีสร้าง Trigger: สร้าง Empty GameObject > ใส่ `BoxCollider2D` (ติ๊ก Is Trigger) > ขยายให้ครอบคลุมพื้นที่โซน > ใส่สคริปต์ `ZoneTransitionTrigger` > ใส่ชื่อ `targetLocationId` (เช่น "jungle_edge")
- บอกวิธีติด Camera: เลือก Main Camera > ใส่สคริปต์ `CameraFollow` > ลาก Player GameObject ใส่ช่อง Target

## Step 5: Runtime Test
- Test A: กด Play, เดินด้วย WASD, กล้องต้องตามผู้เล่นอย่างนุ่มนวล ไม่หลุดจอ
- Test B: เดินชน Trigger ขอบเขตโซน (เช่น จาก beach ไป jungle_edge)
  - Console ต้องขึ้น Log ยืนยันการเปลี่ยนโซน
  - `ChibiSpawnerView` ต้อง despawn NPC ของ beach และ spawn NPC ของ jungle_edge ทันที
- Test C: MCP `explore_location` ยังทำงานได้ปกติ (เพราะมันก็ยังอัปเดต `CurrentLocationId` และ Publish Message เหมือนกัน)

# Output
- โค้ดครบทั้ง 3 ไฟล์ (CameraFollow, ZoneTransitionTrigger, PlayerMovementSystem update)
- ยืนยันว่าแก้ `RoundInitializer.cs` ให้ใช้ `GetPlayer()` แล้ว
